**spring的优良特性(后面学完回来斟酌)**

•非侵入式：基于Spring开发的应用中的对象可以不依赖于Spring的API

•依赖注入：DI（Dependency Injection）是反转控制（IOC）最经典的实现

•面向切面编程：Aspect Oriented Programming - AOP

•容器：Spring是一个容器，包含并管理应用对象的生命周期

•组件化：Spring通过将众多简单的组件配置组合成一个复杂应用。

•一站式：Spring提供了一系列框架，解决了应用开发中的众多问题



**spring的模块划分**

**Core（核心）**：**IoC容器、事件、资源、国际化、数据校验**、数据绑定、类型转换、**SpEL、AOP**、AOT

**Testing（测试）**：对象模拟、**测试框架**、SpringMVC测试、WebTestClient

**Data Access（数据访问）**：**事务**、DAO 支持、JDBC、R2DBC、对象关系映射、XML转换

**Web Servlet（Servlet式Web）**：**SpringMVC**、WebSocket、SockJS、STOMP 消息

Web Reactive（响应式Web）：Spring WebFlux、WebClient、WebSocket、RSocket

Integration（整合）：REST 客户端、Java消息服务、Java 缓存抽象、Java 管理扩展、邮件、任务、调度、缓存、可观测性、JVM 检查点恢复

# 容器

> 介绍

组件：具有一定功能的对象(如servlet,service,dao等,像pojo就不算组件)

容器：管理组件（创建、获取、保存、销毁）

servlet就是一个组件, tomcat是一个容器,因此不需要new servlet对象,但是tomcat管理的并不彻底,,只管了servlet但是service和dao都要new. 同时,servlet帮new的servlet是单例的,只new了一个对象



>ioc和di

**IoC：Inversion of Control（控制反转）**

•控制：资源的控制权（资源的创建、获取、销毁等）

•反转：和传统的方式(用啥new啥)不一样了(交给程序,spring发现需要new啥就new啥)

**DI ：Dependency Injection（依赖注入）**

•依赖：组件的依赖关系(不是jar包依赖)，如 NewsController 依赖 NewsServices依赖dao

•注入：通过setter方法、构造器、反射等方式自动的注入,从而不需要自己new对象



控制反转是一种思想,实现的方式就是依赖注入,spring是容器框架用来实现依赖注入, 

因此目前学习的主要目标就是,想办法把组件注入到spring容器中

### @Bean

具体代码:

```java
/**
 * 主入口类,主程序类
 */
@SpringBootApplication
public class Spring01Application {
	public static void main(String[] args) {
		//继承自ApplicationContext:Spring应用上下文
		ConfigurableApplicationContext run = SpringApplication.run(Spring01Application.class, args);
        //这个run就是ioc容器
		System.out.println("run = " + run);

		//看容器中装了哪些组件
		String[] beanDefinitionNames = run.getBeanDefinitionNames();
		for (String beanDefinitionName : beanDefinitionNames) {
			System.out.println(beanDefinitionName);//Spring的默认组件
		}
	}

	//准备一个javabean,给容器中注册一个自己的组件,每个组件都有名字,方法名就是组件的名字 可以通过改方法名或者@bean("这里写名字")
	@Bean                                              //如果组件名重复了,容器里只会有一个组件 按照方法的字母排序或者先                                                          后写的顺序排序
	public Person p() {
		Person person = new Person(); //可以下载插件GenerateAllsetter 直接alt回车生成所有的set
		person.setName("刘玉婕");
		person.setAge(23);
		person.setGender("女");
		return person;
	}
} //注册组件成功后,输出时会有p这个组件
```

## 工厂Bean(实现FactoryBean<>)

如果制造某些对象比较复杂, 不是简单一个注解就能解决的, 那就用工厂方法进行创建

实现FactoryBean<> 泛型里面写 厂所造的类型 

```java
@Component
public class btd implements FactoryBean<Car> { //这个泛型就代表,这个厂是造啥的(在容器中放的组件的类型)
    /**                                          注意: 组件的名字是工厂的名字, btd
     * 工厂的第一个方法,调用此方法给容器制造对象
     * @return
     * @throws Exception
     */
    @Override
    public Car getObject() throws Exception { 
        return new Car();
    }

    /**
     * 工厂的第二个方法,说明造的东西的类型
     * @return
     */
    @Override
    public Class<?> getObjectType() {
        return Car.class;
    }

    /**
     *工厂的第三个方法 是单例? 返回true代表是 false代表不是
     * @return
     */
    @Override
    public boolean isSingleton() {
        return true;
    }
}
```

注意:别忘了加@Component,工厂也要在容器中

```java
public class mac implements Condition {  //实现Condition接口
    @Override
    public boolean matches(ConditionContext context, AnnotatedTypeMetadata metadata) {
```

### @Autowired(重要)

当想在controller使用service不用像下图这样new了 直接UserService userservice;  加上@Autosired就行

```java
@Controller
public class UserController {  
   UserService userService=new  UserService();
}

@Controller
public class UserController {  
    @Autowired
    UserService userservice;
}
```

(此时在控制台run.getbean(UserController.class), 就可以看到userservice=UserService()的地址)



流程为

优先按照类型找到这个组件,如果该类型组件有且只有一个,直接注入,此时名字写什么都无所谓

如果同类型有多个组件,接下来就会按名字找, 找多个组件中名字和注入时写的名字一样的

有多个,且名字找不到对应名字的,那会报错

```java
@Controller
public class UserController {
   @Autowired
   Person person2; //注入person2,此时在控制台查看UserController类的组件,就可以发现person2的信息
}

public class PersonConfig {
    @Bean("person")
    public Person person(){
        Person person = new Person();
        person.setName("刘玉婕");
        person.setAge(23);
        person.setGender("女");
        return person;
    }
    @Bean("person2")
    public Person person2(){
        Person person = new Person();
        person.setName("邹存羿");
        person.setAge(22);
        person.setGender("男");
        return person;
    }
}
```



List<Person>PersonList; 这样写可以注入所有的person类型的组件

Map<String,Person> PersonMap; 这样写可以把所有Person类型组件以及名字注入

### @Qualifier

精确指定,如果有多个Person类型的组件,且写的名字找不到对应的,这时候可以在@Autowire上面写@Qualifier("存在的名字")    就和改名字其实一样

### @Primary

默认组件,在某组件(如person2)的@Bean上加@Primary, 以后就算写Person xxx (xxx不存在), 这时候也会让person2进入组件,xxx成为组件的名字,这时候改组件名写Person xxx(xxx存在) 注入的也只能会是person2了

一旦使用了Primary, 要想真正使用别的组件就只能使用Qualifier组件进行精确指定了

### @Resource(jakarta包的,不是Spring的)

和@Autowired的区别,@resource是java+提供的接口,所有具有容器功能的框架他都支持

Autowired是Spring的,只有Spring支持, resource具有更强的通用性

Autowired可以在括号里写(required=false), 那样就算下面标的东西没有也不会报错(类下有多个组件,但是名字对应不上的情况)

### @Profile(重要)

primary的缺陷,用不同的组件的话,需要不停的去改primary的位置

需求:告诉Spring,哪个数据源哪种情况下才生效

可以利用条件注册 @Conditional

而Profile和conditional比较类似

@Profile("环境标识写啥都行") //当这个环境标识被激活的时候,就会加入下面的组件.要是没表明激活的环境,则会走默认default环境

如果没表明环境,还没定义default的组件,就会报错



personconfig代码如下

```java
@Configuration
public class personconfig {
    @Profile("p") //环境标识
    @Bean
    public Person p1() {
        Person person = new Person();
        person.setName("刘玉婕");
        person.setAge(23);
        person.setGender("女");
        return person;

    }

    @Profile("p2")   //注解里也可以写数组
    @Bean
    public Person p2() {
        Person person = new Person();
        person.setName("邹存羿");
        person.setAge(22);
        person.setGender("男");
        return person;
    }
    @Profile("default")//默认环境表示,不指定的时候就会把p组件放进容器
    @Bean
    public Person p() {
        Person person = new Person();
        person.setName("邹");
        person.setAge(22232);
        person.setGender("男");
        return person;
    }
}
```

## 动态代理

静态代理,每包裹一个组件就需要写一个对应的方法, 很不方便

定义:目标对象在执行之前,会被拦截,执行动态代理的指定逻辑(拦截器的思想)

优点:什么都可以代理

缺点:不好写,复杂, **被代理的对象必须有接口**,如果转实现类的话,会报错

AOC的目的就是简化这个动态代理



**动态代理的理解代码 ↓**

```java
 @Test
    void contextLoads2() {
        jisuanqi target = new jisuanqiimpl(); //目标对象,原生对象
        
        //动态代理是java原生支持的,不需要创建类
        /*一行代码搞定,但是需要三个参数
        需要传3个参数
        1.目标对象的类加载器 target.getClass().getClassLoader()
        2.目标对象实现的接口(利用反射) target.getClass().getInterfaces()
        3.函数式接口InvocationHandler
            利用Lambda表达式
             InvocationHandler ih =( proxy, method, args) ->{return null;};
             这个InvocationHandler类似于拦截器
             这三个参数中,proxy代表代理对象 (相当于明星的经纪人) 真正的目标对象是target
                        method代表代理对象准备调用目标对象的method方法 
                        args代表方法调用传递的参数
         */
        InvocationHandler ih =new InvocationHandler() {
            @Override   //动态代理的关键就是利用这个invoke方法,在真正执行之前拦截
            public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
                args[0]=0; //拦截,并且将第一个参数设置成0
                Object result = method.invoke(target, args); //执行目标方法,这里的参数就是0和3了-----------关键
                System.out.println("InvocationHandler在运行");
                return result;
            }
        };


//        Object o = Proxy.newProxyInstance(s.getClass().getClassLoader(),s.getClass().getInterfaces(),
//                ( proxy, method, args) ->{return null;}); //可以转为和目标类型一样的类型(强制类型转换)
        jisuanqi o = (jisuanqi)Proxy.newProxyInstance(target.getClass().getClassLoader(),   //反射包下的Proxy
                target.getClass().getInterfaces(),
                ih); //关键是第三个参数
        
        System.out.println("target.add(1,3) = " + target.add(1, 3));  //4             走的是目标对象本身
        System.out.println("o.add(1,3) = " + o.add(1, 3));//传递参数1和3, 但是参数arg[0]变成0了所以为3  走的是代理对象

    }
}
```

```java
@Component
@Aspect //告诉Spring这个组件是切面
public class logaspect {  //准备aspect包,里面写logaspect类
    /*
        告诉Spring以下方法何时何地运行
        何时 :@Before方法执行之前运行 @AfterReturning方法执行返回结果后运行(方法正常返回)
        @AfterThrowing 方法抛出异常执行 @After方法执行之后运行(无论方法是否正常返回)

        何地:写切入点表达式:
  excution(写方法的全签名,简写即可)   全签名是 public int com.atguigu...一直到指定接口.执行方法(参数类型) throw Exception
        如 "execution(int add(int,int))"代表add方法的位置,
          可以写通配符,写*代表所以方法 ..在参数位置代表任意多个参数,任意类型   ..在路径位置代表多个层级
          ("execution(int com.atguigu.maven.spring02.jisuanqi.*(..))") 一般这样写 接口.*(..)
          代表q
         
         */
    @Before("execution(int *(int,int))")
    public void logstart(){
        System.out.println("开始");
    }
    @After("execution(int *(int,int))")
    public void logend(){
        System.out.println("结束");
    }
    @AfterReturning("execution(int *(int,int))")
    public void logreturn(){
        System.out.println("返回");
    }
    @AfterThrowing("execution(int *(int,int))")
    public void logexception(){
        System.out.println("异常");
    }
}
```

```java
@Before("execution(int *(int,int))")
    public void logstart(JoinPoint joinPoint){//这个joinPoint就代表连接点,连接点里有当前方法的全部信息
        //Signature signature = joinPoint.getSignature();//拿到方法全签名
        MethodSignature signature = (MethodSignature) joinPoint.getSignature();//转换成MethodSignature,因为有更多的方                                                                                  法可以调用
        String methodName = signature.getName();//拿到方法名
        Object[] args = joinPoint.getArgs();//参数值
        System.out.println(methodName+"开始,参数列表是"+ Arrays.toString(args));
    }
    @After("execution(int *(int,int))")
    public void logend(){//后置方法可以获取一下名字,这里就不展示了
        System.out.println("结束");
    }
    @AfterReturning(value="execution(int *(int,int))",returning="result")  //写returning指定result接收返回值
    public void logreturn(JoinPoint joinPoint,Object result){  //写Object参数来接收返回值
        MethodSignature signature = (MethodSignature) joinPoint.getSignature();
        String name = signature.getName();
        System.out.println("返回值是"+result);//把返回值输出
    }
    @AfterThrowing(value="execution(int *(int,int))",throwing = "e") //想加上异常的信息,指定e接收异常的信息
    public void logexception(JoinPoint joinPoint,Exception e){//写Exception参数来接收异常信息
        MethodSignature signature = (MethodSignature) joinPoint.getSignature();
        String name = signature.getName();
        System.out.println(name+"方法异常了,错误信息是"+e.getMessage());//把异常信息输出
    }
```

### 环绕通知

@Before @After @AfterReturning @AfterThrowing 这些只是通知方法,不能改变目标方法的参数和内容等,只是管理了代理方法

@Around   可以控制目标方法是否执行,修改目标方法参数,执行结果等



编写环绕通知切面类

```java
@Aspect
@Component
public class aroundaspect {
    @Pointcut("execution(int com.atguigu.maven.spring02.jisuanqi.shuxue.*(..))")
    public void asd() {}
    /*
    环绕通知的固定写法如下
    public Object aroundAdvice(ProceedingJoinPoint pjp) throws Throwable{
    }
     */
    @Around("asd()")
    public Object aroundAdvice(ProceedingJoinPoint pjp) throws Throwable{ 
        //Object是返回值,因为可能会切各种方法,不确定那些方法具体返回类型
        System.out.println("环绕的前置通知");
        Object proceed = pjp.proceed();//继续执行目标方法  这句话类似于动态代理的method.invoke,
        System.out.println("环绕的返回通知");  //异常通知和后置通知需要把目标方法try catch包围,异常写catch里,finally里写后置通知
        Object[] args = pjp.getArgs();//获取目标方法的参数
        //Object proceed = pjp.proceed(这里也可以传参);   如果想修改参数,只需要写args[0] = xxx; 之后把args传入就可以了
        return proceed; //想返回什么就可以返回什么,因此可以修改返回值
    }
}
```



注意:如果给环绕通知包裹一个别的切面类,别的切面类识别不出来原本的目标方法是否有异常了, 因为异常在环绕通知内部被try catch吃了

推荐的做法是 在catch里写throw e; 把异常往上抛,之后在aroundAdvice上 throws Throwable

## @Transactional事务

开启事务

1.在主程序中开启事务管理 (开启的是基于注解的自动化事务管理)

@EnableTransactionManagement



2.要给谁加事务,就给哪个方法上面加注解 

@Transactional



## 事务的细节

### 1.transactionManager:事务管理器

作用是控制事务的获取,提交和回滚

底层默认使用的是 JdbcTansactionManager(通过在主程序自动注入TransactionManager t;之后t.getClass.sout即可查看)



事务的底层原理是, 由事务管理器来控制提交和回滚,还有一个事务拦截器,来控制何时提交以及何时回滚



### 2.timeout:超时时间(秒为单位)

@Transactional(timeout=3)  整个事务一旦超过3秒,事务就会回滚,比如事务中间代码业务很多的时候,测试的时候用Thread.sleep(单位为毫秒)即可

注意:超时这个作用范围仅仅是从事务的开始(方法开始),到最后一次dao(对数据库操作),如果在最后一次对数据库操作之后又有很多代码,只要不再对数据库进行操作,就不算超时.



### 3.readOnly:只读优化

@Transactional(timeout=3,readOnly=true)

只是一个优化项,就是在没代码的方法用他能加快运行速度(没什么需要学的目前)



### 4.rollbackFor:可以指明哪些异常需要回滚

不是所有的异常都会引起事务回滚

异常分为运行时异常(可执行),编译时异常(无法执行)

Spring对异常回滚的机制,运行时异常都回滚,而编译时异常不回滚(编译时异常抛出错误,也可以运行)

@Transactional(rollbackFor={IOException.class}) //这时除了默认的以外,遇到io异常也一样会回滚了



### 5.noRollbackFor:指明哪些异常不需要回滚

用法和rollbackFor类似



### 6.隔离级别(重点)

mysql阶段有对脏读,不可重复读,以及幻读的详细解释

| 隔离级别         | 概述                     | 脏读 | 不可重复读 | 幻读         |
| ---------------- | ------------------------ | ---- | ---------- | ------------ |
| read-uncommitted | 读未提交事务数据         | 是   | 是         | 是           |
| read-committed   | 读已提交事务数据(oracle) | 否   | 是         | 是           |
| repeatable-read  | 可重复度(mysql)          | 否   | 否         | 是(极小概率) |
| serializable     | 串行化和序列化           | 否   | 否         | 否           |



隔离级别在读的事务上添加,不在写事务上添加(添加的方式@Transactional(isolation=Isolation.具体的隔离级别))

注意: 可重复读和读已提交的区别还有, 如果读多个数据(相同的数据,用多个变量赋值), 在运行过程中如果修改数据并提交, 那么读已提交的隔离级别下 数据会发生改变, 但是使用可重复读,多个数据值还是不变的,哪怕删除掉都还有不变的数据值

一般读已提交用的最多



### 7.传播行为(重点)

定义:当一个事务方法内部还有事务,事务该以何种状态存在? 事务属性该如何传播下去.(有小事务和大事务)



(重要)REOUIRED   支持当前事务(大事务),如果不存在大事务则创建新的事务(就是小事务正常创建事务)

SUPPORTS  支持当前事务,如果不存在大事务则无事务(不会创建小事务)

MANDATORY 支持当前事务,如果不存在则抛出异常

(重要)REQUIRES_NEW 创建一个新事务,并在存在大事务时挂起大事务,先执行新事务

NESTED    如果当前存在事务,则在嵌套事务中执行,否则像REQUIRED一样运行

NOT_SUPPORTED 非事务执行,如果存在大事务则暂停

NEVER  非事务性的执行,如果存在事务则抛出异常



需求:如果出错,金额回滚,库存不回滚

@Transactional   //这是大事务

checkout(){

扣减金额; // 点击方法,在具体方法上写@Transactional(propagation =REOUIRED)

扣减库存; //@Transactional(propagation =REQUIRES_NEW) //创建了新事务,不在老事务中了

int i =10/0; //此时大事务就会异常,不会影响新事务

}

如果出错在扣减库存的内部, 则大事务会异常,扣减库存会回滚,扣减金额也会回滚,注意关注异常的传播链

如果在小事务和大事务公用一个事务了(如REQUIRED),小事务里的设置项(属性:如timeout=5)就失效了,以大事务所设置的为准
